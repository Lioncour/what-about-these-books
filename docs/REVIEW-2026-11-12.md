# Code & product review — 2026-11-12

Read-only review of the whole codebase plus a hands-on run of the dev build with the
real 18-book library. Findings are ranked within each section; every one was checked
against the source (file:line) or reproduced in the app.

**Status (same day):** everything below is fixed, including the `handler.ts` Scope refactor,
the embedding abort signal, existing titles and chapter labels (Manage → Tidy), and two of
the product ideas (scope shown per answer, cost shown per answer). Still open: a cheaper
default model for specialists (needs to know which Bedrock models the account can call; the

See the changelog's two 2026-11-12 sections.

## Reproduced in the app

1. **A book named in the question is not the book that gets read.**
   Asked *"In Columbus Day, how does Joe first meet Skippy?"* with the whole shelf in
   focus. `selectBooksForLibrarySpecialists` (`src/lib/chat/specialist-limits.ts:13`)
   picks books purely by semantic seed passages and never looks for a title in the
   question, so the specialists read books 2–7 and the answer opened with *"I don't
   have the actual text of Columbus Day"*. Fix: match catalog titles / series order
   ("book 3") against the question first (`findBooksByTitleQuery` already exists) and
   put those books first, or scope to them.
2. **Cost and latency per question.** That one question took about 45 s and 7 Claude
   calls, ~140k input tokens on Opus 4.6 (Settings → Token usage). Causes below
   (keyword bloat, repeated embeddings, re-asks).
3. **Sources list repeats the same chapter.** The mention-count answer listed 28
   sources: every book's chapter four times ("Columbus Day · Chapter 12" ×4). Collapse
   duplicates per book/position and show a snippet.
4. **Raw filenames as titles.** "paradise expeditionary force book 3 alanson craig",
   "SpecOps Craig Alanson (EPUB)". Open Library already gives edition metadata for
   series; use it (or EPUB metadata) to set a clean `title` and `author` at ingest.
5. **Presence line shows a duplicated librarian name** ("Librarian Hypatia, Librarian
   Hypatia"): `getLibrarianName` in `chat/constants.ts` is not unique per book.
6. Clicking a suggested question only fills the box; it should send.

## Data loss / corruption (fix first)

1. **`restoreBackup` with `backupId: ".."` wipes the data dir.**
   `src/lib/ops-store.ts:191-201` joins the id unchecked; `src` becomes `DATA_DIR`,
   and each entry is `rmSync`'d before being copied onto itself. Validate the id
   against the backup listing.
2. **Restore is undone by the in-memory Vectra index.** `book-store.ts` keeps a
   singleton index whose `_data` was loaded before the restore; the next upsert/delete
   writes the stale index over the restored `index/index.json`. Drop the singleton
   after restore.
3. **No atomic writes anywhere** (`books.json`, `settings.json`, `texts/*.json`,
   Vectra, ops/knowledge/quality/token stores). A crash mid-write of `books.json`
   makes `loadCatalog` throw on every request. Write to `*.tmp` + rename.
4. **Lost update in series reconcile** (`book-store.ts:722-973`): catalog loaded, then
   minutes of Open Library calls, then saved; anything uploaded/deleted meanwhile is
   overwritten (index chunks and `texts/` file remain as orphans).
5. **Ingest ordering** (`api/extract/route.ts` ~476-483): catalog and index are
   written before `saveBookPages`; a failure between leaves a book with no text.
6. **Concurrent index updates**: Vectra throws "Update already in progress" if an
   upload runs during a reindex; reindex `running: true` is persisted with no
   staleness check, so after a crash `/api/reindex` refuses forever.
7. **Reindex overwrites specialist profiles** with empty stubs, and embeds
   `[label]\ntext` where ingest embeds raw text, so citations after a reindex read
   "Unknown location".
8. **`deleteBook` is partial**: knowledge graph, timeline, quality cache, shares and
   chats keep the removed id.
9. `saveChat` writes an unvalidated body as `${chat.id}.json` (`undefined.json`, or
   `..` escaping `chats/`).

## Security (loopback, but reachable from any browser tab)

1. **No Origin/Host check and no local token.** Any web page the user has open can
   `fetch("http://127.0.0.1:3000/api/books", {method:"DELETE", mode:"no-cors", …})`
   (`request.json()` ignores Content-Type), run restore, reindex (Bedrock spend) or
   `aws-status?force=1` (spawns `aws sso login`). Single most important fix: reject
   requests whose `Origin`/`Host` isn't the app's own, or have Electron inject a
   per-launch token.
2. **Path traversal on `bookId`** (`book-store.ts:134,139,542,550,601,618,620`):
   `DELETE /api/books {"bookId":"../settings"}` unlinks `settings.json`. Validate
   `^book-\d+$` or look the id up in the catalog first.
3. **PUBLIC_MODE gaps**: settings, series, chats, safety, reindex, search, workspace,
   token-usage reset, eval (runs Claude), debug chat logs and aws-status POST are all
   open in "public read-only" mode.

## Chat pipeline correctness

1. **Stop doesn't stop the spend.** `handler.ts` never reads `request.signal` and
   `bedrock-claude.ts` passes no `abortSignal`; a cancelled 6-book fan-out runs to
   completion, then `controller.enqueue` throws inside the catch.
2. **Thin orchestrator answer is dropped in streaming mode** (`orchestrator.ts:92-97`,
   `handler.ts:734-757`): the fallback is computed but never emitted once tokens
   have streamed.
3. **Streaming auth retry duplicates output** (`bedrock-claude.ts:106-140`): `full`
   lives outside the retry closure, so every token is re-emitted.
4. **Parallel SSO logins**: `forceLogin` bypasses the in-flight dedupe; six
   concurrent specialists can open six `aws sso login` windows.
5. **Specialist cache hit returns `findings: []`** (`specialist.ts:157-167`), so a
   repeat question has no sources and a worse answer; cache has no model id in the
   key and no invalidation on reindex.
6. **Router kind is decorative**: `router.ts` decides, `handler.ts` re-runs the raw
   detectors per scope branch, so STATUS/logs can disagree with what ran.
7. Any ≥20-char quoted string forces exact-quote mode regardless of intent.
8. ERROR payloads are sent raw; multi-line AWS errors split into junk lines.

## Cost / latency

1. **Keyword "passages" bloat the RAG prompt** (`handler.ts:796-802` and two more):
   every word >3 chars incl. "what/does/about", substring any-keyword match, up to
   500 snippets appended. "What does Skippy think about humans?" ≈ 40k input tokens.
2. **The question is embedded up to ~13 times per request** (seed + 6 specialists +
   6 re-asks); a per-request memo removes all but one Titan call.
3. **Re-ask fires on most specialists** (`specialist.ts:249`: `findings.length < 2`).
4. **Sync disk I/O on the hot path**: `findPageForText` re-reads and parses the whole
   book JSON per rendered section (20+ parses of multi-MB files per query, blocking
   STATUS flushes); `listBooks`/`listSeries` re-read `books.json` ~6× per request.
5. `ensureAwsCredentials` shells out to `aws sts` every 2 min and any failure
   (offline) opens a browser login mid-chat.
6. System prompt is sent in the user turn; use the `system` field and prompt caching.
7. Knowledge graph: up to 39 edges per page with 220-char evidence; a 1000-page book
   adds ~10 MB to one pretty-printed JSON rewritten on every upload.

## Fragile heuristics (`intent.ts`)

- `shouldBypassSpecialists` (`:409`): `hey\b` has no leading `\b`, so **"they"**
  triggers it ("Who are they fighting?" → answered from model memory, no evidence);
  likewise `help me`; and any ≤8-word question without a keyword ("Does Joe
  survive?", "What's the twist?") goes to the hallucination path.
- `extractWhoIsTarget` (`:402`): "Who is Joe in love with?" → searches "Joe in love with".
- `looksLikeMainCharacterQuestion`: "Is Skippy the main character?" → dumps entity list.
- `looksLikeLibraryCountQuestion`: "Which books in my library mention Mars?" → "You have 18 books."
- Mention count: "How often does Joe appear nervous?" → counts "Joe"; "the Elders" → "Elders".
- `looksLikePopCultureSurvey`: "Any references to Mars?" → Star Trek list.
- `extractQuotedText`: lazy `.{20,}` spans two titles in `Compare "A" and "B"`.

## Structure

- `handler.ts` is three ~300-line copies of the same flow (all / series / book).
  Extract a `Scope` object (`semantic`, `keyword`, `exactQuote`, `countMentions`,
  `label`) and one linear pipeline; the mention-count block appears 6×.
- Dead code after the early returns (`:437-447`, `:666-672`, `:1016-1022`,
  `:1380-1386`); late `resolveLibraryCommand` re-checks always null.
- Raw `controller.enqueue(TEXT)` in seven places bypasses `emitAnswer` and its log.
- `page.tsx` (1200 lines) and `book-store.ts` (1200 lines) would both split cleanly.

## Electron / packaging / CI

- Fixed port 3000 with no in-use check: `waitForServer` accepts a 200 from any
  server, so the window can load a foreign app while Next dies with EADDRINUSE.
- `nextProcess.kill()` doesn't kill the `next dev` tree on Windows; orphans keep the port.
- `startNextServer` can throw inside `whenReady().then(startApp)` with no catch.
- No tests at all; CI runs only typecheck + lint, never `next build` or
  `electron-builder`. `@types/node ^20` with Electron 40 (Node 22); lockfile drift.
- `extract/route.ts:277-284` installs a global `uncaughtException` handler per upload
  to paper over an `epub2` bug; handlers stack on concurrent uploads.
- `postdist` writes user config into the builder's home dir.

## Product ideas (beyond bugs)

- Per-question cost/latency badge (the data is already in token-usage).
- A "scope chip" showing which books a question will be asked against, editable
  before sending; would have caught finding 1.
- Cheaper model for specialists (Haiku/Sonnet) with Opus only for the orchestrator;
  `modelRouting` exists but defaults all to Opus.
- Clean titles/authors at ingest; cover + title edit in Manage.
- Let the eval harness cover full chat answers (today retrieval only), then make
  the intent heuristics regression-tested.

## Done well

Deterministic counts/quotes over stored text; clean stream protocol with legacy
decode; defensive JSON parsing in specialists; bounded concurrency and normalised
vectors in embeddings; validated settings; random expiring share tokens; Open
Library calls with timeouts and caches; Electron hardening (single instance,
contextIsolation, window-open deny, navigate allowlist, standalone packaging).

## Suggested order

1. Origin/Host check + `bookId`/`backupId` validation (an afternoon).
2. Atomic writes helper used by every store; drop the Vectra singleton on restore.
3. Scope by named book; `they`/`help me` bypass fix; abort signal through to Bedrock.
4. Per-request embedding memo, keyword-passage cap, re-ask threshold, page cache.
5. Refactor `handler.ts` around a `Scope`, with the eval harness extended first.
